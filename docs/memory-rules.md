# NPC 识别与记忆规则

> 从 AGENTS.md §4 抽离的完整规则：slug 归一化、mod 全名校正、注入与优先级、摘要模板与归类边界、空闲兜底、超限重试、重写缓存机制 1。
> 速查摘要与红线见 [AGENTS.md](../AGENTS.md) §4。

- **slug 归一化**：剥品阶/外观前缀（形如「前缀·名字」）、心境后缀（形如「名字~心境」→
  「名字」，心境记入 state.variants）、括号身份、尾随独立数字（形如「名字 3」→「名字」）、
  文件系统非法字符；无名 NPC 按场景兜底（`商贩-<场景>`）。
  同一人的多种全称都记入 state.rawNames。
- **mod 全名 → 原名**：游戏装了 mod 后 NPC 全名会变，**不同 mod 全名不同但都包含原名**
  （实测 `## 角色设定` 形如「前缀·名字+编号」）。而 `## 角色背景` **以原名开篇**——
  因此以背景为锚校正：背景里出现过完整全名 → 数字属真名，保留；否则取最长前缀使背景以其开头
  （「名字+编号」→「名字」）；再退一步取背景中出现过的最长前缀。
  **只在候选名含数字时校正**，普通名字不动（避免误伤）；真名本身含数字者已用边界用例验证安全。
  实测校验：历史 19 个角色全名 **0 处变化**，仅 mod 编号被正确剥离。
- **sessionId**：`ses_` + `sha256("npc:"+slug)`，用于内部标识/日志。
- **请求分类**：system 含「你是对话记忆压缩器」→ 原样透传不建档（游戏端内压缩）；
  无游戏模板（ping 等）→ 原样透传；其余含 `## 角色设定` → NPC 对话。
- **注入**：仅当该 NPC 已有真实记忆时，在最后一条 user 前插入一条 system
  （"你本人的长期回忆"），首轮不注入；**记忆中的身份/关系/经历优先于游戏 system 的
  角色设定、背景与当轮状态描述**（唯一例外是 JSON 输出格式）；若与外置提示词冲突，
  以提示词为准；标注"玩家所述，未经证实"的内容不得当事实承认。
- **格式强化**：NPC 轮且 system 含 `## 输出格式` 时，补一条极简提醒，确保模型输出
  游戏要求的单个 JSON 对象（实测可消除 flash 偶发回纯文本的问题），不牺牲流式。
- **请求重写（实验性）**：仅 NPC 对话、且确有外置记忆/提示词时触发；重写**全部纯文本
  system 模块**（游戏实测为 7 条左右，含角色设定、场景、任务、输出格式等，且与历史交错）；
  历史对话与玩家消息不动；注入在重写之后进行。每个模块单独校验（`## 输出格式` 内的
  **JSON 结构**必须一致，标题下的说明文字可删改；长度 30%~150%；非 `## 输出格式` 模块
  返回空即视为删除该模块），
  枚举漏值/字段缺失会先用原 schema 自动补回，字段名/类型/多余字段等结构改动仍判失败；
  失败的模块单独回退并记 `rewrite_failed:module<id>:<reason>`，解析失败则全部回退。
  客户端断开时中止重写调用。
- **机制 1「整轮指纹缓存」（2026-10-23，非分段）**：`cache.mode=exact` 时启用，默认 `none`。
  键 = 最终发给上游的完整请求体（全部 system 模块原文及顺序、外置记忆、外置提示词、
  model/temperature/max_tokens/thinking）+ 上游地址 + `CACHE_VERSION`。逐字节相同才复用上次
  已校验通过的原始回复，并**重新跑一遍解析/校验**；输入、模型或重写 prompt 任一变化都会 miss，
  仍走完整重写。只有 `status=done` 入缓存，`failed/partial` 下次重试。
  **全局存储**：每个机制一个 `data/rewrite-cache-<mode>.json`（机制 1 =
  `data/rewrite-cache-exact.json`），运行期在内存 LRU 中读写，变更后防抖异步落盘；
  默认上限 1000 条，超出淘汰最久未用，TTL 默认 7 天。键里已含 slug，不需要按 NPC 分文件。
  首次加载会把旧版 `data/npcs/<slug>/rewrite-cache.json` 合并进全局文件，成功落盘后删除旧文件。
  只加速、不改语义；`mode=none` 时请求体与未加缓存逐字节一致。管理页用「短名 + 悬浮说明」的
  单选行展示机制，后续机制在 `REWRITE_CACHE_MODES` 与前端 `CACHE_MODE_OPTIONS` 中追加。
- **摘要 prompt：7 分区「状态卡」模板**（2026-10-27 重构，治流水账）。
  产物是**可逐条查的状态卡**，不是事件日记：固定 7 分区
  **【身份与称呼】【关系】【经历与进度】【未了之事】【赠予往来】【习惯与忌讳】【同场】**，
  标题原样保留、顺序不变、一个都不能少；无内容写「（无）」。
  **写法硬约束（模型必须遵守）**：
  ① 一行只写一件事、≤60 字；② 【经历与进度】【未了之事】用 `1. 2. 3.` 编号，其余分区一行一句；
  ③ **禁止复述式前缀**「她已认下 / 她已应下 / 她已受住 / 她已放话 / 她已当面 / 对方已 / 他后来」；
  ④ **禁止过程连接词**「于是 / 随后 / 接着 / 又 / 这一回 / 当场 / 之后」；
  ⑤ 只写仍影响当下的内容，已了结且无后续影响的过程不写；⑥ 同一件事只写一条，后来变化直接改那一条；
  ⑦ 细节要写足（能落到具体做法/进度/约定就写具体），总字数上限 = `maxMemoryChars`。
  **旧【玩家所述，未经证实】分区已删除**：玩家的身份/关系宣称若 NPC 未承认，**不写进记忆**；
  只有因此留下未解决分歧，才写进【未了之事】并标「（她未认）」。
  这解决了旧模板的「可被字面满足但意图落空」问题——旧要求「用现在时陈述状态」，
  模型会把「某日她做了 A」改写成「**她已认下 A**」，字面合规、实质仍是逐条复述。
- **摘要窗口按「行号水位」切片**（2026-10-27，修掉流水账根因）：
  `state.json` 的 `lastSummaryLine` 记录 `conversations.jsonl` 已消费到第几条（按非空行计）；
  每次摘要**只喂水位之后的新对话**（`conversationsAfter`），成功后推进水位，失败保持原值下次重试。
  旧行为是「取最近 `recentEntries` 条（=20 轮）」，而每 `everyTurns`（4）轮就摘要一次
  → **同一段对话被反复摘要约 5 次**，每遍都在旧结果上叠加细节，这是流水账膨胀的直接原因。
  老档案没有该字段 → 首次摘要沿用旧窗口，成功后水位一次性推到文件末尾，之后自动接管。
- **超限处理：先重试、再按板块压缩**（`overLimitRetries`，默认 2）。实测模型的字数纪律很差：
  prompt 写「目标 4800、不要超过 5000」，自然产出仍在 5010~5358，且**会把 `max_tokens` 用满**
  （早期 `maxTokens` 偏小时出现 `finish=length`，正文被从中间切断）。
  因此摘要器做了三件事：
  ① **调用时给足输出额度**：`min(maxTokens, ceil(上限 × 1.15 / 1.4))`，保证能自然写完、不半截截断；
  ② **超限先回喂重试**：把上一次输出回喂、明确要求「至少减掉 N 字」，并授权合并条目、
     大幅精简低优先级分区，只死保【身份与称呼】【关系】【未了之事】；重试只接受
     「明显变短」（< 上次 -40 字）的结果，否则直接进兜底；
  ③ **兜底不用「砍尾」，而是 `fitMemorySections()` 按板块预算压扁**：
     七个分区全部保留（不再整段丢弃），每次从「最长且仍高于保底」的分区上按行裁，
     只裁掉刚好需要的字数，被裁的分区末尾标「…（本节较早内容已省略）」。
     实测 4949 字 → 上限 4900/4600/4000/3000 时分别压到 4863/4509/3974/2944，七个分区始终齐全。
- **稳态下的小幅压缩不算异常**：记忆长期贴着上限时，模型每轮会多写 100~200 字，
  压缩掉这部分属于正常预算。只有**砍掉比例 >8%** 才记 `memory_over_limit:A>B` 警告；
  其余情况记 `fitted:true` + `trimmedRatio`，管理页显示中性标签「已按板块压缩 N 字」。
  （0.15.1 之前这里是无条件告警，导致玩家每轮都看到「记忆 5136 字超出上限 5000 字，已截断」。）
- **注入裁剪按分区优先级**（2026-10-27，修掉「先砍身份」）：`loadMemory` 超预算时
  **不再用 `body.slice(-maxChars)`（保留尾部、丢弃头部）**，而是按
  【赠予往来】→【同场】→【习惯与忌讳】→【经历与进度】→【未了之事】→【当前关系】（旧格式）→【关系】→【身份与称呼】
  的顺序处理：正文比「必须砍掉的量」还小就整段丢，否则只软裁剪该段（保留首尾 60/40）。
  **身份与关系永远最后才动**；只有连底座都放不下时，才退化为全局首尾裁剪。
  裁剪只发生在注入时，**磁盘上的 `memory.md` 不动**，末尾会注明「本次未注入：…／已截短：…」。
- **配置守卫（写得出来 + 注入得到）**：`maxMemoryChars` 受 `maxTokens` 物理约束
  （中文约 1.4 汉字/token），运行时生效上限 = `min(maxMemoryChars, floor(maxTokens × 1.4))`；
  `injectMaxChars` 至少为「生效上限 + 200」，否则写得进、注入不到。
  配置加载时会**只把仍是老默认值的项**升级到新默认（3200→5600 / 3000→5000 / 2500→4000 /
  90000→120000 / 40→60），玩家自定义过的值保持不变；`maxTokens` 不足时自动提到
  `ceil(maxMemoryChars / 1.4)`。管理页会显示交叉校验提示。
- **空闲兜底（[idleFlusher.js](../src/memory/idleFlusher.js)）**：`state.turns > state.lastSummaryTurn`
  （有落后轮次）**且**距 `state.lastSeen` 超过 `idleFlushMs`（默认 5 分钟）时，后台补压一次。
  解决两类空档：① 尾部不足 `everyTurns` 轮（如聊到第 5 轮下线，原本要等累计到第 8 轮才进记忆）；
  ② 累计聊不满 `everyTurns` 轮的短会话（`memory.md` 原本永远为空、下次见面注入 0 字）。
  补压发生在玩家已离开的时段，**不增加任何响应延迟**；定时器 `unref()`，不阻止进程退出。

## 游戏请求格式备忘（2026-10 实测）

- system 模块化拼接、段落可增减乱序、偶有无关碎片；身份只认 `## 角色设定`。
- 回复是一个 JSON 对象（`content`/`emotion`/`control`/`intent{...}` 等字段，话题任务还会多出
  任务相关字段）。**具体字段与枚举取值以当轮 `## 输出格式` 为准**，程序只做容错解析，
  不硬编码任何具体枚举或取值。
- **游戏官方下发的 system 模块默认原样透传**：程序不对其内容做任何假设、改写或裁剪。
  唯一例外是玩家显式开启「请求重写」（实验性）时，由上游模型删除/改写与外置内容冲突的描述，
  且 `## 输出格式` 必须逐字保留、校验失败即回退原文。
  这类模块的具体条目会随游戏更新而变，**不要**把任何具体条目写进本项目文档或常量。
- 游戏自带近期多轮历史与要事回顾；外置记忆定位是跨会话的更长期补充。
- **真实 system 是 CRLF（`\r\n`）文本**——写解析正则时：换行分隔符后的空白只能用 `[ \t]`
  （用 `\s` 会跨行吃掉下一行），取值只能用 `[^\r\n]`（用 `[^\n]` 会带出多余 `\r`），
  跨行匹配要写 `\r?\n`。历史日志里的样例是 LF，**不要照它推断真实输入**。
